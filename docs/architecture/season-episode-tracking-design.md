# 多季度追踪与集数范围优化调研

## 结论与现状

可以优化。创建订阅向导已经允许勾选多个季度，提交时将所选季号传给获取动作；底层存在按季度区分的 `TrackedSeason` 和集状态。但订阅策略按账号与作品保存，向导明确说明各季共用规则，因此当前不能在策略面板里给每季分别保存起始集或独立策略。多季选择不等于各季独立配置；实际入队结果仍可能受已有追踪、存储及任务状态影响。

现有 `episodeFilter` 是资源筛选字符串，空值表示不限制，支持 `S01-S03`、`E01-E10`、`S02E05` 等形式，没有开放式“从第 N 集起”的独立字段。`E05-E10` 适用于任意季；各条款以**或**匹配，`S02;E05-E10` 不表示第二季的第五至十集。资源无法识别出集号时，有限范围可能将其排除，整季包不能仅凭包名保证文件逐一符合范围。

创建向导中 `computeEpisodeFilter` 在选择部分季度时用季号字符串替换用户填写的范围，预览使用的草稿与最终保存的范围也可能不同。这会丢失用户范围，是实施本方案前应修复的行为。当前代码依据：

- `apps/web/features/acquisition/components/subscription-modal.tsx`：多季选择、预览、`computeEpisodeFilter`、先保存策略再派发获取。
- `apps/web/features/acquisition/components/subscription-modal-fields.tsx`：范围输入与“各季共用策略”提示。
- `apps/web/app/api/titles/subscription-policy/route.ts`：按账号和作品读取、保存策略及语法校验。
- `packages/workflow/src/execution/subscription-policy.ts`：范围解析和或匹配。
- `packages/workflow/src/persistence/subscription-policy-store.ts`、`packages/workflow/src/execution/runner-v2.ts`：策略持久化与任务策略快照。

## 建议交互

创建向导的第一步选择网盘和多个季度，每季展开一行：追踪开关、起始集（默认 1）、结束集（默认不限制）。显示“第 2 季：从第 5 集起”之类的自然语言摘要；支持一键应用相同范围到所选季。集数未知时仍允许开放结束，已知总集数仅作为提示及输入校验依据，元数据变化不应静默改写用户设置。特别篇第 0 季单独标注，不与默认普通季混选。

作品详情的每季卡片增加“追踪设置”，可单独调整起止集、暂停或恢复该季；保存前显示受影响季和已排队任务的快照行为。公共画质、关键词、优先级组继续作为作品默认规则；首期只提供逐季范围，若需要不同画质等规则，再增加明确的“继承作品规则 / 本季覆盖”选项。修改某季不得改变其他季，应用到多季需明确选择目标。移动端使用可访问的数字输入、明确标签和行内错误，避免长下拉列表；对不连续集数保留高级选择作为后续能力。

## 数据与执行设计

1. 新增账号、作品、网盘工作区和季号作用域的季追踪配置，保存 `startEpisode`（整数、至少 1）、可空 `endEpisode`、启用状态和版本。明确同一作品不同网盘互不覆盖；特殊季和单集映射单独处理。具体唯一键应与现有工作区作用域核对后落库。
2. 集数范围是追踪目标，作品策略是资源质量与关键词过滤；有效目标先按季的结构化范围限定，再与作品策略作交集。不要将季范围编码进 `episodeFilter`，也不要靠拼接当前或语法模拟交集。已有规则的转换必须先分类：可无歧义转换才自动迁移；混合或规则保持原语义并提示核对，禁止静默扩大或缩小范围。
3. 在缺集计算、预览、手动获取、自动巡检、候选筛选和最终入库文件筛选使用同一个范围判定器。先判断季，再判断集；整包先作为待检查候选，实际文件识别后逐文件判定。无法识别季集的文件进入待复核或拒绝自动入库，并说明原因，不能当作命中；不要将所有文件都拒绝后标记任务成功。
4. 入队时在同一事务中冻结选中季的有效范围及作品策略、规则版本和工作区。运行中修改只影响以后入队的新任务；已排队任务继续使用原快照，界面显示快照时间与版本。旧快照、版本不支持、无策略或无季配置的处理必须明确并可观测，不能意外回退到最新配置。
5. 先保存目标与策略，再按现有动作入队；多季部分入队失败时返回逐季结果及可重试状态，避免重复任务。取消追踪与删除已下载文件分离，已存在媒体不因缩小范围被删除。开始集更改后仅重新计算缺集和未来任务，不自动批量重试或删除。

范围判定可用纯函数及小型策略接口表达（全部、起止范围、未来的离散集），编号映射通过适配器处理标准季集、绝对集号和特殊篇；暂不引入通用状态机框架。创建向导继续用现有步骤状态，任务状态继续复用队列状态；只有出现跨请求复杂生命周期再考虑状态机。范围采用区间比较 O(1)，不展开成大型集合；批量按作品加载配置，避免每个候选触发数据库查询。动漫绝对集号与 TMDB 季内集号不能猜测换算，缺少可信映射时提示人工确认。

## 可复用基础设施和外部参考

- 已有 React 19、原生数字输入、TypeScript、Zod、季/集实体、策略解析和预览、模板、SQLite 与内存仓储、入队快照和 Vitest；先复用这些基础设施，不需要新增依赖。
- [Sonarr 官方 FAQ](https://wiki.servarr.com/sonarr/faq) 区分剧集和单集监控，也区分持续监控新资源与主动搜索历史缺集；其动漫绝对编号处理说明了编号体系需要单独设计。[Wanted 文档](https://wiki.servarr.com/sonarr/wanted)支持批量改变单集监控状态。适合借鉴监控状态与历史搜索分离，但不要假设 PanSou 的能力与其索引器相同。
- [MoviePilot 官方订阅文档](https://github.com/jxxghp/MoviePilot-Wiki/blob/main/subscribe.md) 将初次搜索、后续增量刷新及补漏搜索分开，并允许编辑单个订阅的站点范围；可借鉴分层配置及限制重复搜索的思路。本文不据此断言其具体起始集 UI 行为。
- 无障碍数字输入若后续需要复杂本地化、键盘及触控行为，可评估 [React Aria NumberField](https://react-spectrum.adobe.com/react-aria/NumberField.html)；当前简单整数场景优先原生控件。已有 Zod 可用于 API 结构化范围校验，避免引入规则引擎。

## 验收与防回归

- 创建 S1 从第 5 集、S2 从第 2 集且结束第 8 集；验证预览、保存、刷新、巡检和入队快照一致，S1E4/S2E9 排除而 S1E5/S2E2 命中。
- 多选部分季度并填写范围，确认提交不覆盖输入；验证当前 `S02;E05-E10` 的或语义不能被误当作交集。覆盖空值、反向、零、非整数、上限未知和元数据更新。
- 已追踪两季后仅修改一季，另一季及其他账号、网盘均不变；批量应用仅影响勾选季。暂停/恢复不删除已有文件。
- 保存后入队再修改，验证旧任务保持快照、新任务采用新配置；并发保存与入队事务一致，重启后 SQLite 与内存仓储行为一致。
- 对单集、跨季合集、整季包、混合已存在与缺集文件、无编号和绝对编号动漫分别检查最终文件门禁及可解释结果；避免空结果被当作成功。
- 模拟部分季入队失败、重复提交、权限越界、旧数据迁移、无效/未知快照版本与预览失败；验证不静默扩大追踪范围。浏览器检查窄屏、键盘、屏幕阅读器、错误反馈和范围摘要。

建议顺序：先修复覆盖和预览不一致；再实现结构化季范围及迁移、统一判定与快照；最后接入逐季编辑和整包文件门禁，使用模拟资源验收后再进行真实网盘验证。

## 本轮落地范围

首期复用现有账号/作品订阅策略，不新建季追踪表：`season_episode_ranges` 保存每季唯一一条 `{ seasonNumber, startEpisode, endEpisode }`，结束集 `null` 表示不限。这样起止集可独立编辑，策略读取仍是一次，现有预览、自动筛选和入队快照也能沿用同一条数据链。作品详情编辑器会显示该作品已知的所有季度；创建向导只编辑当前选中的季度，隐藏的其他季度配置会保留。

`episodeFilter` 保留原有语义并与结构化季范围取交集。预览和资源候选筛选对能够识别的单集按范围判断；无法从候选标题识别季集时先保留候选继续解析，避免把整季包误当作单集删除。资源展开后，最终视频文件门禁要求能识别季集；不符合范围或无法识别的文件不会通过策略门禁。队列预留时冻结整份策略（包含逐季范围），之后修改只影响新任务。

首期只新增逐季起止集，不增加按季度覆盖画质词、独立启停或追踪状态；这些仍使用既有作品策略和追踪流程。资源包若展开后文件名仍无法识别季集，会安全拒绝并提示人工处理；当前不会自动拆分、重命名或删除包内文件。数据库存储解析、API 重复季度校验、入队快照及范围边界均有回归门禁。
