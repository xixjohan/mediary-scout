# 订阅策略快照、优先级组与模板设计

调研日期：2026-11-07；实现状态：2026-11-07 已完成首版。此前的调研见 [订阅策略执行方案](subscription-policy-execution-research.md)。

## 结论与边界

三项能力已在现有 SQLite 与工作流架构内实现首版：策略随入队任务写入不可变快照；有序优先级组参与候选过滤和排序；模板支持按账号隔离的增删改查及应用。模板是用户主动应用的配置副本，后续编辑模板不会改变已应用作品策略或已排队任务；重试沿用原快照，用户若要应用新策略须创建新任务。

本方案延续作品级策略，季范围仍由任务指定；不扩展自动洗版、跨账号共享模板或任意用户脚本。优先级影响候选选择，不赋予 Agent 绕过硬过滤的权限。

## 快照与事务（已实现）

当前实现把快照作为 `workflow_runs.payload` 中的 `subscriptionPolicySnapshot` 保存，让任务与快照随仓储事务一起写入。字段包括 `schemaVersion`、`evaluatorVersion`、`capturedAt` 和完整规则；`policy: null` 显式表示入队时未配置策略。快照不包含凭据、动态 `lastTakenAt` 或网盘链接。当前没有内容摘要字段或编译缓存，规则组规模较小，先避免不必要的缓存与失效逻辑。

SQLite `reserveWorkflowRun` 使用 `BEGIN IMMEDIATE` 事务，在策略读取前获取写锁，再读取策略并写入新任务及快照；内存仓储在无 `await` 的预留临界区实现相同语义。对 `already_active` 返回既有任务，不覆盖其快照。保留账号、网盘和作品隔离。快照适用于电影、剧集获取、巡检及替换请求。

worker 通过任务 ID 和账号作用域读取快照；当前只接受 schema/evaluator 版本 1。搜索候选与最终实际视频文件复核共享同一硬规则，候选排序另按优先级组执行。自动重试、进程崩溃恢复和手动重试复用原任务快照；新建任务读取新策略。历史任务若无快照返回 `legacyUnknown` 并失败关闭，提示重新创建任务，不会回退读取当前策略。策略变更只影响之后成功入队的新任务。

历史任务不能推断原规则：读取没有快照的任务时返回 `legacyUnknown`，执行层提示重新创建；没有迁移旧任务 JSON 或线上统计。冷却水位 `lastTakenAt` 是随时间变化的运行状态，不属于不可变任务快照；快照保存的是 `cooldownDays` 配置值。

## 优先级组与模板

保留全局硬条件：所有包含词需命中，任何排除词命中即拒绝；集数规则未知时拒绝。其后按用户排列顺序评估优先级组：组内条件 AND，首个匹配组决定等级；完全空白的占位组跳过；未配置组时沿用现有行为，配置了组但无组匹配时拒绝并给出原因。候选组内用源结果顺序作为稳定平局键；文件校验继续应用硬条件和集数，不假定每个文件都带有资源包级优先属性。

候选列表由服务端先应用硬规则与优先级组匹配，未命中任何配置组的候选会被排除；其余候选按首个匹配组的顺序稳定排序后交给 Agent。该首版表达“优先级偏好”，Agent 仍可选择排在后面的合规候选；若需求要求硬性逐组降级，需要进一步分批暴露候选，并定义组耗尽/降级状态。候选标识贯穿检查和转存；最终文件门禁复核硬条件和集数，不要求每个视频文件名复现资源包级优先词。预览显示通过、拒绝原因及匹配组，不保证上游资源仍然可用。

模板以账号隔离，保存名称、规则内容和创建/更新时间；支持新建、更新、删除、列表及将完整内容复制到作品策略草稿。更新/删除模板不改已应用作品策略和既有任务快照；快照包含展开后的规则，不依赖模板 ID。当前未实现内置只读模板、导入导出、模板描述或引用计数；模板应用会整体替换表单草稿，保存作品策略后才生效。

前端已在订阅向导和作品策略面板提供模板套用；策略面板支持模板新增、更新和删除。两个入口均支持优先级组新增、编辑、上移/下移和删除；当前没有启停开关。空白组会跳过，避免刚添加的空组吞掉之后配置的等级。入队后修改策略只影响新任务。任务详情的快照可见性尚未实现。

## 设计模式、性能与风险

使用现有搜索源适配器将候选字段规范化，纯函数 `matchPolicy` 组合硬过滤及有序组并返回结构化判定。持久化通过仓储预留流程封装事务；模板是受限 JSON 规则数据，不建立复杂工厂体系。复用现有工作流状态机处理 queued/running/终态和重试，不为规则组另建状态机。

每任务读取一次快照并按候选执行纯函数匹配；目前无单独编译缓存。服务端限制最多 8 组、每组最多 12 个词、词长最多 64 字符；创建模板前检查账号下最多 50 个，但该数量检查不是跨请求原子配额。用户正则仍由 JavaScript RegExp 执行，灾难性回溯风险尚未由本次实现消除；切换 RE2 等受限引擎需单独定义语法。尚无性能基准，不承诺提速；后续应采集事务等待、快照大小、候选数、匹配耗时与 p95。

## 实施结果与验收门禁

1. 已完成：仓储契约、SQLite 与内存实现均在任务入队时固定显式空策略或完整策略快照；历史无快照任务失败关闭。
2. 已完成：worker 使用快照，候选硬过滤和最终视频文件校验继续使用确定性匹配器。
3. 已完成首版：有序优先级组编辑/预览/匹配、按优先组稳定排序、账号隔离模板 CRUD 与模板应用。

已覆盖：策略编辑后已排队任务仍使用原快照；内存与 SQLite 仓储契约验证订阅、替换和暂存恢复任务的快照捕获及账号范围；匹配器验证组顺序、空白组跳过和无匹配；文件门禁不把包级优先组条件误用于每个视频文件；策略 API 验证组限制；模板 API 验证新建、列表、更新、删除及账号隔离；快照缺失、旧任务和未知 evaluator 版本失败关闭。仍需补充：并发双连接事务压力、模板操作不影响既有应用策略/快照的端到端测试、浏览器窄屏验收、优先级是否需要 Agent 严格逐组降级、性能基准和 JavaScript 正则安全专项。

本轮聚焦验证为 9 个测试文件共 438 项；工作流构建、类型检查和改动源码 ESLint 通过。未做提交、推送、部署、线上浏览器验收或性能基准。
