# 订阅策略配置与执行方案

调研日期：2026-11-06；实现状态更新：2026-11-07。假设“MP”指 MoviePilot。

## 结论与现状

可以支持类似 MoviePilot 的订阅策略。建议先完成现有规则在真实获取链路中的硬执行，再扩展优先级和模板；Agent 可以辅助识别和排序，但最终转存前必须由确定性的规则检查。

当前 `tracked_seasons` 保存追踪目标，`subscription_policies` 按账号和作品保存一套策略，`workflow_runs` 记录执行；策略没有季级主键。原有候选适配器支持可选 `policyFilter`，但生产调用链此前未注入。下方“当前实施状态”记录本轮已完成和仍未覆盖的部分；实现结论来自源码与本地测试，未做线上实测。

## 当前实施状态（2026-11-07）

已完成：

- 电影及剧集获取流程在工作流运行前按账号和作品读取已保存策略；包含词、排除词和集数条件会在资源适配器把候选交给 Agent 之前过滤，并在真实视频文件入库时复核。
- 剧集最终按季移动文件时逐个复核视频文件名；电影整理和任务结束时复核本轮新落盘的视频。集数规则遇到无法识别集数的文件会拒绝入库；字幕随对应视频处理。拒绝项不会被计为已获取，用户可删除不符合规则的文件或选择合规文件后继续。
- 已保存的自定义搜索词接入电影、剧集自动任务提示，原始片名结果不足时指导 Agent 将片名与自定义词组合查询；仍受现有搜索预算与搜索词清理逻辑约束，且自定义词只扩展召回，不改变硬过滤条件。
- 未追踪作品可按媒体类型预览、读取和保存策略；相同 TMDB 数字 ID 的电影和剧集按类型隔离。
- 订阅向导改为“范围 → 策略 → 预览与确认”三步。剧集详情页新增入口，并把实际选中的未追踪季传给队列；策略保存失败不会创建获取任务。移动端向导使用全屏窄屏布局。
- 第 0 季默认排除；预览请求支持显式季号列表，且预览和候选过滤复用同一匹配器。
- 获取任务在入队事务中固定完整策略快照（含明确的无策略状态），worker、自动重试和恢复从任务快照读取；历史任务缺少快照时失败关闭并提示重新创建，不会偷用当前规则。
- 支持最多 8 个有序优先级组。通过硬条件与优先级匹配的候选按组序稳定排序后交给 Agent；最终视频入库时复核硬条件和集数，不要求每个视频文件名复现资源包的优先级关键词。
- 订阅策略模板支持按账号隔离的列表、新建、更新、删除和应用。应用只复制到当前策略草稿，模板之后的编辑/删除不会回写作品策略或已排队任务。

仍需明确或专项处理：

- 当前优先级组是硬条件通过后的候选排序偏好，Agent 仍能选择排在后面的合规候选；若需要严格最高组优先和组耗尽后降级，应另行定义分批候选与降级状态。
- 历史任务没有入队时规则，现按 `legacyUnknown` 失败关闭；发布时需提示用户重新创建受策略约束的旧任务。
- JavaScript 正则可能遭遇灾难性回溯；本轮没有引入 RE2，也尚无队列 p95、候选规模和大规则集性能基准。
- 尚未完成浏览器实机的移动端策略模板/优先级交互验收。

本轮验证：策略快照、硬过滤/优先级组、SQLite 与内存仓储、策略/预览/模板 API 的 9 个聚焦测试文件共 438 项通过；`npm run build:workflow`、`npm run typecheck` 和改动源码 ESLint 通过。未做浏览器实机验收、全量门禁或线上部署。

## 目标语义

1. 计划定义账号、作品、网盘、追踪季和执行状态；策略定义搜索词、硬过滤、排序及巡检频率。首期延续账号加作品的策略作用域，界面明确各季共享；季级覆盖属于后续需求。
2. 默认无策略时维持现有获取行为。硬条件中所有包含词均需命中，任一排除词命中即拒绝；集数范围取交集，未知集数在配置范围时拒绝并说明原因。搜索词扩展查询，不作为资源准入条件。
3. 有序优先级组内条件为 AND，组之间按顺序择首个匹配；启用优先级但所有组均未命中时拒绝。硬排除始终先于优先级；同优先级使用稳定且可解释的排序。未配置优先级则允许通过硬条件的候选。
4. 自动巡检、手动获取、重试和 Agent 工具调用均经过相同策略执行点；人工查看原始搜索结果可以展示未通过项，但转存入口仍需检查。替换、恢复和历史任务入口须逐一盘点并明确适用策略；不能依靠提示词约束执行。
5. 规则版本随任务入队固定为快照；重试沿用该快照。策略编辑只影响新任务，任务详情展示规则版本与拒绝原因。读取失败或规则非法时终止受策略约束的任务并提示，禁止静默放行。

## 具体方案

统一入口先校验并保存追踪目标与策略，在同一数据库事务内写入任务及策略快照，提交后再通知 worker；失败不得显示成功。为未追踪作品提供创建订阅时配置策略，详情面板在未追踪时显示创建入口。多季选择要把实际选中的季传到后端，不应把多个选中季扩大为所有剩余季。已存在策略保留并明确展示生效范围。

在获取编排层加载任务策略快照，构造一次 `PolicyEvaluator`，传给所有搜索适配器；在标准化候选后、Agent 决策前执行硬条件，并在最终转存前对所选资源再次核验。整季资源需在获取清单后逐文件校验，无法确认集数时暂停或拒绝，避免整包绕过范围。候选标识和文件标识须贯穿搜索、选择与转存，避免检查对象与实际转存对象不一致。仅通过的候选交给 Agent；Agent 输出也要在服务端核验。输出通过、拒绝原因、规则版本、匹配字段和数量，避免记录凭据及完整敏感链接。

使用适配器将各搜索源结果转换为统一候选模型；用小型策略组合实现硬过滤与排序，返回结构化判定而非仅布尔值。任务生命周期沿用现有工作流状态，必要时补充“策略无匹配”“策略错误”“等待人工确认”等结果，定义合法状态迁移及重复执行幂等；无需为每条规则引入独立状态机。预览与执行共享同一个 evaluator 和相同规范化逻辑，预览展示数据来源、未知字段、拒绝原因及策略版本，不承诺资源之后仍可用。

策略保存时校验长度、词数、集数表达式和正则语法；限制候选数量、名称长度、并发和执行时间。正则应在受控引擎中编译一次并按版本缓存，避免灾难性回溯；缺失引擎或不支持的表达式要明确报错。每任务读取一次策略快照，候选字段解析一次，先做廉价排除再匹配复杂规则；保留现有搜索缓存和限流，策略版本应纳入依赖策略的缓存键。搜索网络开销预计主导，但必须以候选数、规则数、CPU、p95 延迟和上游请求数基准验证，不预设性能收益。

## 实施顺序与回归门禁

1. 梳理所有任务入口及转存入口，统一创建、持久化和快照；修复未追踪面板与错误反馈。
2. 接入硬过滤及最终转存复核，覆盖手动、自动、重试、Agent 和整季文件；统一预览和执行。
3. 增加有序优先级、模板及可解释 UI；洗版在确认现有替换、回滚与去重语义后另行设计。

行为回归至少覆盖：未配置策略；包含词全部命中、排除优先、大小写与正则错误；季集范围、未知集数、整季包含范围外文件；多季选择；不同账号和作品隔离；创建策略失败不得排队或报成功；策略编辑后任务快照稳定；预览与执行对相同样本判定一致；Agent 返回被拒绝资源无法转存；自动、手动、重试及各适配器均不能绕过；冷却只影响指定巡检；重复任务幂等；恶意正则和超长名称在预算内失败。使用真实组件/API 和模拟网盘验证转存前门禁，并进行窄屏与桌面交互验收。对现有策略上线前应提供受影响数量及规则预览，避免静默改变用户订阅结果。

需要进一步确认：所有替换和恢复入口的执行边界、网盘目录内文件名可用性、策略快照的数据迁移与事务边界，以及 RE2 部署兼容性。实施前用调用链和实际样本核实这些事项。
