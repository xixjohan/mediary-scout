# 订阅集状态丢失与自动搜索：修复结果及实机恢复

日期：2026-11-14（Asia/Hong_Kong）。对应[原始调研](2026-11-14-auto-subscription-search-and-episode-inventory-investigation.md)。本文件记录后续修复，原始调研中的只读范围描述仅适用于上一阶段。

## 1. 已确认的根因

### 1.1 采集失败抹除库存事实

生产数据库确认任务 `bd51c6d5…`、`42218692…` 最终异常均为 `PAN115_RATE_LIMIT: API call budget exhausted before listItems; maxCallsPerOperation=295`。任务已经调用过转存、移动和获得标记，但整个运行最终失败。

当前源码的失败处理对普通采集终态提交空 episodes；重试则重放 claimed 时的旧 episodes。这两种写法都能覆盖较新的 obtained。新增真实 InMemory / SQLite 仓储用例在修复前 18 项均失败：终态清空为 0 行，重试把后来发现的 198 集重新写成未获取。

另一个边界是：已有文件扫描结果、本轮新文件移动结果仅留在内存，直到整个采集结束才落库。即便文件已真实入季，后续模型或预算异常也会让它们始终不显示为获得。已增加“移入季目录后、markObtained/finish 之前模型失败”的整条回归，并验证失败处理仍保留该集及文件关联。

### 1.2 分类丢失导致扫描了另一个空目录

生产记录中《凡人修仙传》为 `type=tv`，绑定的季目录与实际 Anime 下 198 集的目录不同。反向扫描器把 TMDB API 的 `movie/tv` 命名空间直接当作媒体库分类，丢弃了 Anime 分类及动画 genre 信息。后续 worker 依据 `title.type` 选择 TV 分类根，创建/使用另一目录，因而报告目标目录为空。

源码缺陷已用明确 Anime 分类、自动分类 + Animation genre 两种输入复现并修复。这里能确定目录错配及该可复现写入路径；现有记录没有逐次历史分类变更审计，无法证明最初每一次分类覆盖都由同一次扫描触发。

### 1.3 自动搜索真实停止点是后置策略，不是 Jev 全剔除

对任务 `2037cc55…` 的持久化快照与同时间段日志交叉核验：

| 阶段 | 证据 |
| --- | --- |
| 来源 | PanSou 连续失败 3 次，触发 5 分钟熔断；源快照为 degraded |
| 裸标题候选 | Jev 判定 92 条 |
| Jev | 剔除 16 条无关作品，保留 76 条；NSFW 剔除 0 条 |
| 后置策略 | 日志明确 `filtered 76 candidate(s) not matching the work's strategy` |
| agent 可见 | 0 条；旧提示只提到 Jev 的 16 条剔除，还错误地声称“这不是搜索源故障” |

入队策略快照包含必须包含 `1080p`、排除词和 E190 起季范围。历史日志能确定**最后的清空发生在策略层**；旧实现没有保存每条保留候选的最终拒绝枚举，所以不能把 76 条全部进一步断言为同一个具体条件。新实现为后续任务补齐 `missing_term / excluded / episode_filtered / priority_unmatched` 等计数。

下午的手动查询源健康，并聚合返回 844 条候选；它与早上降级来源、后置过滤后的 0 条不是相同输入。手动可见不代表符合自动规则，更不代表可以实际完成转存。没有降低 Jev 阈值、关闭死链保护或放宽用户的 `1080p` 条件。

两部电影也单独复核：修罗雪姬的历史剔除样本为“修罗武神”“Lady Love”等无关作品，目前没有误剔除正确电影的证据；用心棒多数查询原始为空或无关，`大鏢客` 查询有 1 条通过 Jev 后仍未进入最终候选。不能将所有“无资源”统一诊断为模型误筛。

## 2. 本地业务修复

| 修改 | 关键文件 |

| 前置扫描确认文件后立即做幂等库存检查点；保存 provider file ID，修复季目录绑定，保留元数据总集数 | `execution/inventory-checkpoint.ts`、`acquisition-v2/run-tv-v2.ts` |

| 常规单季/全季终态合并较新 obtained，避免覆盖检查点；元数据扩展出现新缺口时重新激活季状态 | `execution/runner-v2.ts`、`persistence/repository.ts`、`persistence/sqlite.ts` |

没有新增依赖或外部服务，继续复用现有解析器、仓储事务、状态模型和候选筛选器。

## 5. 剩余边界

- 未实际转存 E197，候选存在不保证链接和网盘离线通道可用。
- PanSou 早上的熔断已确认，底层为何连续失败的网络/上游细节不在保留日志中；本次没有擅自调整来源地址、并发或超时阈值。
- 本次库存恢复确认非零视频及文件名集号，没有逐文件播放验证。
- 只有目标目录已成功核验的文件才提交；如果移动完成后连核验读取也被拒绝，仍须下一轮对账恢复，不能凭 move 返回值伪造获得。
- 历史通知是当时运行的记录，不随本次库存修复篡改；新的分类提示需部署补丁后由新任务产生。
- 首次全剧订阅只预留首季锁记录：尚未创建追踪记录的后续季不会由检查点擅自创建，其独立持久化仍依赖全剧终态或后续对账。这是既有的多季失败恢复边界；本次没有为了扩大覆盖而绕过取消追踪保护。
