# 已有订阅的手动搜索与入库：现状及方案

## 结论

当前普通用户界面的“获取”主要用于创建追踪：作品或季已追踪时，`requestTrackingAction` / `requestSeasonAction` 返回 `already_tracked`，不会借此重新搜索。详情页“资源检索”是手动查询候选资源，并非一键按现有订阅策略自动搜索并入库。

设置页已有“立即巡检”按钮，可手动触发全局巡检；`POST /api/workflows/run-type3?force=1` 是受 worker secret 保护的另一入口。两者处理巡检集合，不能针对单条订阅；`force` 只明确绕过时间门槛，不代表绕过所有并发、状态或业务约束。进一步核查发现 MCP 的 `triggerAcquisition` 当前仅返回成功消息，并没有创建任务，不能作为实际触发入口。详见同目录的系统盘点文档。

因此可以新增“立即搜索缺失资源”：选择当前账号、网盘、作品和季，后台复用已有监测获取流程及订阅策略，搜索成功后按现有转存、验证和入库流程执行。用户得到的是任务已受理和进度，而不是立即入库成功。

## 现有基础设施

| 能力 | 可复用位置 | 注意事项 |
| --- | --- | --- |
| 用户与网盘范围 | `apps/web/app/actions/acquisition-actions.ts`、worker 的账号与网盘上下文 | 服务端重新校验归属，不能信任浏览器传来的账号或目录 |
| 巡检 | `packages/workflow/src/execution/worker.ts` 的 `runScheduledType3Monitoring` | 当前按追踪状态批量处理；抽取单目标执行单元，不能通过全局 force 代替单目标 |
| 互斥与持久化 | `WorkflowRepository.reserveWorkflowRun`、活动页与通知 | 同一账号、网盘、作品及季原子去重，并与替换、整理和恢复任务互斥 |
| 资源筛选 | `subscription-policy-filter.ts`、现有策略存储和工作流 | 手动与定时共用硬过滤、搜索词、范围和实际入库校验，不直接让提示词决定规则 |
| 限流与并发 | worker 的按网盘并发控制、资源查询冷却、115 API guard | 用户反复点击也应有限流、去重和明确的等待提示 |
| 状态管理 | 现有工作流状态，项目已依赖 `xstate` | 当前用现有队列状态即可；复杂交互才考虑复用现有状态机库，不必新增队列产品 |

工作区存在尚未提交的订阅策略、快照和多季相关改动；部署的提交不一定包含这些工作区改动。实现时应先核对最终合并版本及策略快照实际接口，避免假定未提交能力已经上线。

## 业界参考

- [Radarr FAQ](https://wiki.servarr.com/radarr/faq)：区分持续监测新资源和用户主动搜索历史缺失资源；作品详情和 Wanted 页面可发起搜索。
- [Radarr Library](https://wiki.servarr.com/radarr/library)：提供单项、选中项及筛选范围的搜索入口。可借鉴明确的执行范围，不宜默认一键重扫所有订阅。
- [MoviePilot 订阅说明](https://wiki.movie-pilot.org/subscribe)：定期补搜与订阅监测分开，并强调对站点的请求压力；可借鉴限频和补漏语义。

本项目已有任务持久化、调度、互斥、状态展示及 `xstate`，不需要为单项手动触发引入 BullMQ、Redis 或新状态机库。外部项目的搜索行为可借鉴，实际网盘权限和转存边界仍沿用本项目的适配器。

## 具体方案

1. **入口**：在已追踪作品及每季行提供“立即搜索缺失资源”；电影对应作品，剧集对应单季。可在订阅列表提供同一操作。多季批量执行作为后续扩展，先避免误触造成大量请求。
2. **服务端命令**：新增面向当前会话的单目标命令，参数只包含作品、季和网盘标识；校验登录、所有权、追踪状态、网盘和必要配置。不要暴露 worker secret，也不要允许客户端指定任意 CID。
3. **原子受理**：以账号、网盘、作品、季为幂等范围，复用数据库事务和活动任务互斥；返回 `queued`、`already_running`、`not_tracked`、`not_ready` 或 `throttled`。成功受理立即返回任务 ID，前端跳转活动页或显示进度。
4. **执行**：从现有巡检提取单目标用例，复用缺集计算、策略过滤、搜索、转存、验证和入库；保持其他季独立。策略应在入队时形成不可变快照，若现有快照设施尚未合并，先完成其接线再开放入口，不能静默改为执行时读取导致规则漂移。
5. **状态和恢复**：沿用 `queued → running → succeeded/failed` 等既有生命周期；无缺集、未上映或无资源应显示明确结果。配置错误不盲目重试，瞬态错误继续沿用有限退避；取消和崩溃恢复遵循现有队列规则。
6. **频率与性能**：单目标执行不扫描所有订阅；限制同一目标重复触发并提示冷却，复用按网盘并发和 API 预算。冷却和幂等必须在服务端共享持久化或原子存储中生效，不能只依赖按钮禁用或单进程内存。

适配器负责各网盘差异，策略组件负责资源筛选；任务编排负责状态转换和互斥。使用现有边界即可，避免为单一按钮引入新的策略框架。手动搜索默认补齐缺失内容，不隐式启用洗版或覆盖；如需强制重搜已入库内容，应另行明确交互及安全规则。

## 回归与验收门禁

- 已追踪单季可受理并最终进入现有获取流程；未追踪、无权限、错误网盘被拒绝。
- 同一目标并发点击、定时巡检与手动执行竞争时只保留一个活动任务；不同季及网盘按既有并发规则运行。
- 入队后修改策略不会改变该任务快照，必含、排除、搜索词、集数范围等与自动路径结果一致。
- 无缺集、未上映、无候选、配置缺失、限流、执行失败分别显示准确结果；仅瞬态失败按既有规则重试。
- 验证 115 连接级 CID 范围、范围外拒绝写入、重复转存与目录保护；不向真实网盘写入测试夹具。
- 验证用户切换账号或网盘时任务不能越权，手动操作不修改其他季追踪状态；重启后任务状态可恢复。
- 浏览器检查按钮忙碌态、重复点击、排队反馈、活动/通知跳转，以及移动端单季操作。
