# 订阅手动补搜与逐集状态同步方案

## 目标和已确认事实

在已追踪作品的详情页，用户可以对指定季度发起一次使用当前订阅策略的后台补搜，并在活动页看到结果。电影沿用现有独立逻辑。具体实例数据尚未只读核验，以下是源码确认的机制与可能触发条件，不将缺少逐集记录断言为该实例的事实。

- 详情季行的按钮取决于 `missingAiredCount`；缺集看板在逐集列表为空时会由汇总值推算，因此两者可能不一致。后台 `manualSearchReadiness` 只检查已有逐集记录；空列表会返回 `no_missing`。
- `syncSeasonAgainstMetadata` 仅在总集数或已播数改变时构建逐集状态；数值未变但记录为空或部分缺失时直接返回。故简单地先调用该函数不足以初始化记录。
- `runQueuedType3Monitoring` 已提供后台元数据同步，但同步失败被记录后继续运行；自动巡检遇到空逐集列表则跳过。`reserveWorkflowRun` 已提供按范围预约、去重和入队策略快照。
- `subscription-missing.ts` 以 `airStatus === aired && !obtained` 判定缺集；详情计数使用 `displayState`，看板还有额外回退。需统一语义，并明确 `provider_ahead`、`unknown` 和部分记录的处理。

## 推荐处理流程

1. 页面显示已追踪季度的补搜入口；已确认无缺集、同步中、任务运行中、无权限分别给出明确原因。逐集信息不完整显示“集数状态待同步”，不把推算集号描述为确定缺集。按钮与看板共享一个纯函数结果，例如 `needs_sync | missing | complete | unknown`，保留逐集状态与汇总推算的来源。
2. 服务端验证账号、网盘、目标、权限及网盘授权；按账号、网盘、作品和季度限定范围。记录用户请求并复用原子预约，获取现有活跃任务或产生新的任务，冻结策略快照。明确区分“同步后搜索”的排队与已实际完成搜索，避免声称已经入库。
3. Worker 在执行补搜前读取当前追踪状态，按任务账号解析元数据配置并同步。修复同步函数：即使汇总值未变化，只要逐集集合缺失或不完整也安全补齐；合并保留已获取状态、文件关联、标题与日期等信息。外部请求不放在数据库长事务内。
4. 同步后在同一作用域重新读取并校验追踪和集数；需用事务或版本比较保护合并写入，避免覆盖同步期间新增的文件和取消追踪。以权威逐集状态重新计算缺集：有缺集才执行搜索；无缺集明确结束为无操作；无法确认时任务失败并提供可重试原因。不可在同步失败后拿推算数据继续转存。
5. 执行前再次检查取消追踪、权限/授权与任务取消状态；复用现有任务锁、幂等记录和策略快照。网络调用设超时及有限退避重试；认证失效、无权限等永久错误不盲目重试。文件转存侧必须复用已有去重，不能仅靠前端禁用按钮。

实现时须先核验现有 SQLite `reserveWorkflowRun`、逐集写入事务和执行器对空集的行为；若无法原子合并，应增加有条件更新或独立同步阶段，不能假设内存快照始终新鲜。`syncOption()` 当前仅在 live search 可用，且元数据适配器使用当前账号配置；后台多账号执行时应确认使用任务所属账号，缺配置时返回明确错误。

## 状态和反馈

建议将已有任务状态扩展为可观察阶段：排队 → 同步集数 → 判断缺集 → 搜索 → 完成/无缺集/失败。阶段可放在现有进度或审计事件中，最终状态仍使用既有任务状态；刷新后由服务端恢复。重复点击返回同一活跃任务，状态未同步、配置缺失、认证失败、同步超时、已取消追踪分别给出明确反馈。历史通知的重试入口属于可选后续项，不应将只读历史记录误认为新补搜结果。

## 性能与边界

每次手动触发只同步目标季度，复用现有 TMDB 缓存和请求超时；对同账号/网盘/季度合并并发请求，并限制全局同步并发。不要在页面渲染时主动对所有季度执行外部请求。元数据与搜索分别计时和记录失败类别，日志避免凭据；按需限制重试次数、索引器调用量与后台队列深度。同步失败不应导致无限轮询，也不应把暂未获取到元数据当作无缺集。

## 实施顺序和验收

1. 先补最小行为测试：汇总值不变且空/部分逐集记录时同步能补齐；保留乱序已获取集与文件关联；元数据失败不会进入搜索。
2. 实现共享缺集状态和前端呈现，覆盖空记录、部分记录、已齐、未播、未知和超前状态；明确禁止将汇总推算当权威集号。
3. 修改预约和 Worker 同步流程，验证重复请求、定时巡检竞争、执行期间取消追踪、并发入库、账号/网盘隔离、同步失败、重启恢复与策略快照。
4. 覆盖电影、MCP 与活动重试现有入口，确保返回状态语义一致；分别验证无缺集、鉴权失效与配置缺失。
5. 开发容器部署后，使用隔离测试数据在浏览器展开季度，验证按钮、同步中、失败、排队和活动结果；用受控索引器及测试目录完成一次端到端搜索。记录请求次数和任务数，确保没有重复任务或跨网盘写入。

验收不能仅凭按钮出现或健康接口成功；必须确认任务实际经历同步与权威缺集判断，并可在活动页区分无缺集、失败与实际获取结果。
